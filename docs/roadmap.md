# 路线图

本页记录公共仓库的交付范围，不表示能力已经实现。具体接口和实施顺序由评审后的正式设计与实施计划确定。

## 第一阶段：本地消费闭环

以 SpiffWorkflow 为流程内核，提供函数、配置输入、本地命令、本地文件交付和核查节点。产品仓库定义策略、输入输出连接、条件分支与验收规则。

统一运行入口提供引导、执行、收尾核查阶段展示，以及逐步审批、明确步骤结果、原始输出和详细错误报告。只读与跳过步骤不请求变更确认；变更步骤在具体动作确定后确认。普通执行失败停止；独立核查的普通失败继续并汇总，契约错误或中断停止。

交付一个完全本地的文件安装示例：填写目标目录、观察文件、交付或复用、检查内容和权限、汇总结果。消费方通过自己的安装脚本组合节点。

构建本地 wheel，在独立消费目录安装实际产物，验证成功、跳过、拒绝、失败、核查汇总和依赖准备后的离线执行。不使用 editable 安装或源码路径代替包交付。不要求 Docker、独立引擎或常驻服务。

## 后续范围

- 按实际需求增加 SSH、pyinfra 和 OpenTofu 节点；所需工具提前准备，缺失时明确报错，不自动下载工具链。
- 提供指导下游设计部署流程的 skill，与公共 API 和简单示例共同维护。
- 开发成熟后准备 PyPI 分发，核对包名、账号认证和发布流程；第一阶段不配置发布设施。

具体产品的接入和迁移属于消费仓库，不列入本仓库的实施阶段。
